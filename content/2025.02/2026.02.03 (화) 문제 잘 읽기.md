# [⭕️ 잃어버린 괄호](https://www.acmicpc.net/problem/1541)
#알고리즘 #백준

# 1. 문제
- 입출력
	- 숫자, '+', '-'로 이루어진 수식이 주어졌을 때 적절히 괄호를 쳐서 최솟값을 출력

## 2. 접근
- 접근 방식
	- 괄호를 여러개 칠 수 있기 때문에 - 부호가 한 번이라도 나오면 뒤의 숫자를 모두 뺄 수 있음
- 막힌 지점
	- 괄호의 개수
		- 문제를 잘못 읽어서 괄호를 하나만 칠 수 있는 줄 알았음
		- - → + 로 바뀌는 모든 값을 벡터에 저장한 뒤, 가장 큰 값을 하나만 빼려고 했음
		- 수식을 순차적으로 읽으며 숫자를 토큰화 했을 때, 
		  부호의 변화는 현재 토큰이 아니라 앞으로 주어질 토큰에 영향을 미치기 때문에 파싱이 어려웠음

## 3. 핵심 포인트
- 문자열 파싱
	- [페이지 세기](obsidian://open?vault=content&file=2025.01%2F2026.01.12%20(%EC%9B%94)%20%EB%AC%B8%EC%9E%90%EC%97%B4%20%ED%8C%8C%EC%8B%B1) 문제에서 학습한 string → int 파싱을 활용할 수 있었음
