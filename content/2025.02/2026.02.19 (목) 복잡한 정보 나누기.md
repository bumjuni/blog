# [⭕️ 베스트앨범](https://school.programmers.co.kr/learn/courses/30/lessons/42579)
#알고리즘 #프로그래머스 #자료구조

> [!abstract] 요약
> - 모든 정보를 한 번에 관리하는 구조체 보다는 RDB에서 테이블을 나누듯이 관심사에 따라 정보를 나누는 것이 더 좋음
> - `sort()` 에서 람다 함수 사용하기
> 	- `sort(v.begin(), v.end(), [] (int a, int b) { return a < b; });`

## 1. 문제
- 입출력
	- 두 배열 genres(장르), plays(재생횟수)가 주어졌을 때 각 장르별로 최대 2개의 노래를 아래 기준에 따라 정렬하여 출력
	  ① 장르의 총 재생 횟수가 많은 순서
	  ② 각 노래의 재생 횟수가 많은 순서
	  ③ 재생 횟수가 같다면 고유 번호가 낮은 순서

## 2. 접근
- 접근 방법
	- 취합해야 하는 정보
		1. 각 장르의 총 재생횟수
		2. 각 장르에 속한 노래
		3. 각 노래의 고유번호(= 초기 인덱스)
		4. 각 노래의 재생횟수
	- `struct`로 구조체를 생성하거나, 필요한 정보를 따로 취합한 자료구조(`map`, `vector` 등) 생성
		- 모든 정보를 한번에 관리하는 구조체 보다는 데이터베이스에서 테이블을 분리하듯이 장르와 노래 정보를 구분하는 것이 좋다고 생각하였음
	
- 구현
	- `genre_played`: `unordered_map`, {장르명, 총 재생횟수}
	- `genre_musics`: `unordered_map`, {장르명, {고유번호, 재생횟수}}
	
	1. `genre_played`로 1번 조건에 따라 장르를 정렬
	2. `genre_musics`에서 2, 3번 조건에 따라 노래를 정렬
	3. `genre_played`에서 정렬된 장르의 순서대로 `genre_musics`의 노래를 최대 2개 뽑기

- 아쉬운 점
	- 흩어진 정보, 특히 노래의 인덱스 정보를 통합해서 관리해야 해서 구현이 다소 복잡했음
	- `pair`를 사용하다 보니 `.first`, `.second`와 같이 접근하면 어떤 것을 의미하는지 알 수 없어 코드가 복잡해짐
	- `compare`함수를 직접 선언했는데, 람다 함수로 구현했다면 정렬 코드와 정렬 기준이 붙어 있어 깔끔했을 것 같음

## 3. 핵심 포인트
- 람다 함수 선언
	- `[] (arg1, arg2) { function };`
- 람다 함수 선언과 동시에 실행
	- `[] (arg1, arg2) { function } (10, 20);`
- `sort`의 `compare`함수를 람다 함수로 생성
	- sort(v.begin(), v.end(), [] (int a, int b) { return a < b; });
