# [⭕️ 스택 수열](https://www.acmicpc.net/problem/1874)
#알고리즘 #백준 #스택

> [!abstract] 요약
> - 데이터의 수명을 고려하는 것은 중요함
>  - 반드시 모든 값을 입력받은 뒤에 계산을 시작할 필요는 없음
>  - 실시간으로 값을 입력받으며 계산할 수도 있음
>  (비교가 계산의 전부인 경우 굳이 queue에 저장한 뒤 pop하지 않아도 됨)
>  
>  - 나의 문제 풀이 방식은 입력, 비교, 출력을 위한 공간을 따로 할당하는 양상을 보이나, 메모리를 고려한 풀이법도 중요해 보임

## 1. 문제
- 입출력
	- N과 N개의 숫자 배열이 주어졌을 때, 스택에 1부터 N까지의 숫자를 push, pop하여 해당 숫자 배열을 만들 수 있는지 판단하여 연산 순서를 출력

## 2. 접근
- 접근 방식
	- `seq`라는 queue에 숫자 배열을 모두 입력받고, 
	  `stk`이라는 vector에 1부터 N까지 push 또는 pop
	- 무한 루프를 돌며
	  `stk.back() == seq.front()`라면 `stk.pop_back()`, `seq.pop()`
	  그렇지 않으면 1증가한 숫자를 `stk`에 삽입
	- 성공 조건은 `seq.empty()`
	  실패 조건은 `next > N && (stk.empty() || stk.back() != seq.front()))`

- 막힌 지점
	- 성공 조건과 실패 조건을 분기하기가 어려웠고, 모든 예외 사항을 포함하고 있는지 알지 못함
	- 주어진 수열을 저장한 `seq`는 queue라 FIFO, 현재 테스트 중인 스택 `stk`는 stack(vector)라 LIFO인 점에 헷갈림

## 3. 핵심 포인트
- 입력과 동시에 계산 
	- 문제에서 주어진 값은 비교한 뒤에는 더이상 쓸모가 없음
	- 반드시 모든 정보를 입력받은 뒤에 계산할 필요는 없음
	- `cin`으로 하나씩 입력받으면서 현재 수열과 비교해도 됨
	⇒ 성공 조건은 단순히 입력이 끝났을 때 수열이 완성될 경우,
		실패 조건은 N까지 push했는데도  입력값과 다른 경우

- 메모리 고려
	- 여태까지의 나의 문제 풀이 패턴은 주로 입력 값, 비교 값, 출력 값을 위한 공간을 하나씩 만들고 있다는 것을 깨달음
	- 이렇게 자꾸 데이터를 저장하다 보면 메모리가 과다하게 소모될 수 있음
	- 공간 복잡도를 고려하거나, 불필요한 공간을 최소화한 문제 풀이 방법을 고민해 볼 필요가 있음

# [⭕️ 일곱 난쟁이](https://www.acmicpc.net/problem/2309)
#알고리즘 #백준 #문법 

> [!abstract] 요약
> - `v.erase(v.begin() + i)`로 인덱스 i의 요소를 삭제할 수 있음

## 1. 문제
- 입출력
	- 9명의 난쟁이의 키가 주어졌을 때 합이 100이 되는 7명의 키를 오름차순으로 출력

## 2. 접근
- 접근 방식
	- 입력 후 오름차순으로 정렬
	- 2중 for문으로 합이 $전체 난쟁이의 키의 합 - 100$이 되는 두 난쟁이의 인덱스 찾기
	- 해당 인덱스를 빼고 출력

## 3. 핵심 포인트
- `erase`
	- 굳이 인덱스를 제외하고 출력하지 않아도, 벡터에 `erase`로 바로 요소를 제거할 수 있음
	- `v.erase(v.begin() + i)`
	- 이때 `i`는 인덱스
