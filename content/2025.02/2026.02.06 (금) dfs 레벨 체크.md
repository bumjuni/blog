# [❌ N과 M(9)](https://www.acmicpc.net/problem/15663)
#알고리즘 #백준 #DFS

> [!abstract] 요약
> - DFS에서 중복 값을 피해서 탐색하는 방법
> 	- 값을 정렬한 뒤 동일한 레벨에서 이전 값과 뽑을 값이 같은지 비교

## 1. 문제
- 입출력
	- N, M, 중복이 있는 N개의 숫자가 주어졌을 때 만들 수 있는 길이 M의 유일한 수열을 출력

## 2. 접근
- 생각해본 방법
방법 1. 중복인 수와 중복이 아닌 수를 구분하여 수열 생성
	- 중복인 수는 언제 뽑히면 안됨?
		⇒ 해당 조합이 존재할 때
		⇒ hash table처럼 `hash({2, 4}) = true` 와 같이 중복된 수열을 거를 수 있음

방법 2.  중복인 수는 언제 다른 수처럼 행동?
		⇒ 중복인 수가 이미 하나 뽑혔을 때
	- 뽑힌 상태와 안뽑힌 상태는 어떻게 구분?
		⇒ 원래 상태를 저장해야 함
		⇒ 구현 실패
	- 입력 값을 정렬하면 마지막에 뽑힌 수와 현재 뽑으려는 수와 중복인지 알 수 있음
		⇒ M (수열의 길이)이 1이라면?
		⇒ 구현 실패

방법 3. 중복된 수를 특수하게 처리
	- 중복이 아닌 수들로 먼저 수열 생성
	- 중복인 수를 k개 뽑아놓은 뒤 수열 생성
		⇒ 중복인 수가 여러개일 경우는 경우의 수가 너무 많음
		⇒ 구현 실패

방법 4. DFS 트리에서 `visited[i]`를 돌려놓는 시점을 조정
	- 원래: `dfs()`호출 이후, 상위 레벨로 올라갈 때
	- 조정 후: 루트 레벨로 올라갈 때 일괄적으로
		⇒ 트리 depth가 깊어질 경우 수를 전부 기억해야 함. 불가능

방법 5. 중복인 수를 따로 관리
	- `{2, 4, 4}`가 주어졌을 때 `{2, 4}, {4}`로 격리하고, 
	  우선 `{2, 4}`에서 수열을 만들되 4를 이미 사용한 경우 (`visited[4] == true`) 격리한 중복 숫자를 사용
	⇒ 매번 중복 수가 있나 확인해야함. 조건 분기가 복잡함.

- 막힌 지점
	- hash table으로 수열을 매번 저장하는것 외에는 중복 수를 판단하기 위한 적절한 조건 분기 방법을 찾지 못함
	- hash table은 공간적으로 비효율적이라 생각하여 적절한 조건 분기 지점을 찾고 싶었음

## 3. 핵심 포인트
- 동일한 레벨에서 비교
	- 방법 2-2 (입력값을 정렬하고 뽑으려는 수와 수열의 마지막 비교)는 서로 다른 레벨 / 가지에서 비교하고 있기 때문에 실패함.
		- 수열의 마지막 (→ 레벨 d) vs 뽑으려는 수 (→ d+1)
	- 동일한 레벨 d, 즉 동일한 for문에서 수열의 마지막을 저장한 뒤 비교하면 `M = 1`이라도 가능함 
	- 핵심은 `answer.back()`을 바로 사용하는것이 아니라 `int last = answer.back()`을 저장한 뒤 비교하는 것
