# [❌ 에디터](https://www.acmicpc.net/problem/1406) 
#알고리즘 #백준 #스택 #문법 

> [!abstract] 요약
> - 스택 활용 → 데이터가 변하지 않는 부분과 변하는 부분이 고정되어 있다면, 데이터를 나누기 
>   
> - c++ STL `list` → 삭제 시 `cur = lk.erase(cur)`로 반드시 다음 요소의 주소를 받아야 함

## 1. 문제
- 입출력
	- 하나의 문자열이 주어졌을 때 다음 명령어를 받아 문자열을 편집하는 에디터를 구현하고, 결과 출력
	- `L`: 커서를 왼쪽으로 한 칸 이동 (문장의 맨 앞에서는 무시)
	- `R`: 커서를 오른쪽으로 한 칸 이동 (문장의 맨 뒤에서는 무시)
	- `B`: 커서 왼쪽의 문자를 하나 삭제 (문장의 맨 앞에서는 무시, 커서는 오른쪽 문자열을 동일하게 가지도록 이동해야 함)
	- `P $`: `$`라는 문자를 커서 왼쪽에 추가

## 2. 접근
- 접근 방식
	- 배열이나 문자열 같은 선형 자료구조에서 인덱스로 이동, 삽입 삭제를 구현
	
- 막힌 지점
	- 위 방법은 $O(n)$이므로 문제 제한 시간(0.3초)에 맞지 않음

## 3. 핵심 포인트
- 스택 활용
	- 커서를 기준으로 양 옆의 문자열을 각각 스택에 넣고, 커서의 이동에 따라 각 스택의 `top`을 양쪽으로 `push`, `pop`
	- 중요한 것은 **"삭제 시 커서 오른쪽의 문자열은 그대로"** 라는 말에서
	  커서를 기준으로 **왼쪽과 오른쪽의 자료구조를 나눈다**는 생각을 하는 것
	
- 링크드 리스트 활용
	- c++의 STL `list` 자료구조를 활용하여 링크드 리스트로 구현
	```
	#include <link> // 링크드 리스트 STL import
	
	// 선언
	link<int> lk
	link<int> lk2(3); // 요소 3개를 0으로 초기화
	link<int> lk3(5, 1); // 요소 5개를 1로 초기화
	
	// iterator 활용
	link<int>::iterator pt = lk.begin(); // 첫번쨰 요소를 가리킴
	pt++; // 다음 요소
	pt--; // 이전 요소
	
	// 삽입
	lk.push_front(7);
	lk.push_back(3);
	lk.insert(cur, 4); // iterator가 가리키는 곳에 4를 삽입
	
	// 삭제
	lk.pop_front();
	lk.pop_back();
	cur = lk.erase(cur); // iterator가 가리키는 요소를 삭제한 뒤, 다음 요소의 주소를 반환
	
	```

	- 구현 당시 `lk.erase(cur)`이라고만 썼더니 iterator `cur`가 free된 메모리 주소를 여전히 가리키고 있어 segmentation fault가 발생했음
	  ⇒ `cur = lk.erase(cur)`로 반드시 다음 요소의 주소를 받아야 함

# [❌ 1874 스택 수열]()

> [!abstract] 요약
> - 문제의 상태 정의 후 가능한 행동 정의
> 	- '이 상황이면 어떤 코드, 저 상황이면 어떤 코드'와 같이 무작정 조건을 분기 X
> 	  
> - 자료구조 사용 시 `empty()`를 통해 segfault 방지 습관화

## 1. 문제
- [2026.02.02 (월) 데이터의 수명](obsidian://open?vault=content&file=2025.02%2F2026.02.02%20(%EC%9B%94)%20%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%9D%98%20%EC%88%98%EB%AA%85) 

## 2. 접근
- 접근 방식
	- 반복문에서 필요한 만큼만 입력받는 방식으로 다시 풀어봄

- 막힌 지점
	- 반복문에서 종료 조건 설정이 어려웠음
		1. 불가능하다고 판단한 경우, 나머지 입력 값을 모두 무시하고 종료
		2. 불가능 판정의 조건을 어떻게 줘야 하는지
	- 따라서 내 풀이 코드를 GPT에게 주며 무엇을 놓치고 있고, 어떤 사고가 부족하냐고 물어봄

## 3. 핵심 포인트
- 종료 조건
	- 나의 코드: `cur > N && stk.back() != num`
		- `cur`변수는 1부터 증가하며 스택에 하나씩 push하는 용도의 변수
		- `cur > N`이면 더이상 push할 수 있는 수가 없으므로 수열 생성 불가능
		- `stk.back() != num`이면 스택에서 꺼낼 수 있는 수와 수열의 수(`num`)가 다르므로 불가능
		
	- 잘못된 이유
		- `cur > N`은 중요하지 않음
		- 우리가 판단할 값은 **현재 스택 top이 원하는 값인가?** 이지 숫자를 다 썼는가가 아니기 때문
		
	- 올바른 조건: `stk.back() > num` ⇒ 불가능
		- `stk.back()`이 `num`보다 작으면 새로운 숫자를 넣으면 됨
		- `stk.back()`이 `num`과 같으면 pop하면 됨
		- `stk.back()`이 `num`보다 크면 더이상 할 수 있는 일이 없음
			⇒ 이는 `if`에서 `stk.back() == num`을 검사할 때 `else`문으로 분기하여 처리할 수 있음

- segfault 방지하기
	- 스택에서 값을 조회하거나 꺼낼 때 `!stk.empty()`로 segfault를 방지하는 예외 처리 코드를 항상 작성해 주는 것이 좋음

- 올바른 사고
	- 지금 상태에서 가능한 행동을 찾고, 없으면 실패
	1. 문제의 상태 먼저 정의
		```
		① 현재 push할 숫자 cur
		② 현재 스택 상태
		```
		
	2. 가능한 행동 먼저 정의
		```
		A. cur <= num → push 가능
		B. stack.top == num → pop 가능
		C. 둘다 안되면 → 실패
		```

	- 모든 상태를 고려하려고 하면 오히려 망함
		- "혹시 내가 생각 못한 제3의 상황이 있지 않을까?" X
		- 상태를 명확하게 정의하는 연습이 필요
