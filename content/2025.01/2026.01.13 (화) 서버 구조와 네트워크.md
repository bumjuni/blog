> 1. 혼자 개발할 때는 웹/인증/모니터링/DB 서버가 나뉘어 있지 않고 한 컴퓨터에 있었으니까 나눠서 관리하는게 굉장히 생소하다. 어떤 전략으로 서버를 나누고 관리할까? 
>
> > [!todo]- 서버를 나누는 기준
> > 1. 역할 기준
> > 	- 웹 서버: 요청 수신
> > 	- 인증 서버: 신원 확인

> 1. 중앙집중식 처리 시스템은 어떻게 동작할까? 클라이언트가 없다면 어떻게 이용하지? 
> > [!todo]- 중앙집중식 처리에서 클라이언트의 유형
> > - 클라이언트가 반드시 PC일 필요는 없음
> > - 서버의 역할은 **계산과 데이터 처리**
> > - 클라이언트의 역할은 **입출력 창구(터미널)**
>
> 2. 왜 신뢰성이 필요한 은행, 보험사에서 중앙집중식 처리(메인프레임)를 주로 사용할까? 어떤 점이 클라이언트-서버 시스템보다 더 신뢰성을 제공하지?
> > [!todo]- 메인프레임 vs 클라이언트-서버
> > - 메인프레임
> > 	- 하드웨어 이중화
> > 	- 메모리, CPI, I/O를 모두 교체하여 무중단 서비스 가능
> > 	- 트랜잭션 무결성 반드시 보장
> > 	- 검증된 아키텍처
> > - 클라이언트-서버
> > 	- 확장성
> > 	- 비용 효율적
> > 	- 대신 failure를 소프트웨어로 처리해야 함
> >  
> >  ⇒ 은행은 속도보다 정확성을 택한 것

## 네트워크란 (p.34-35)

> [!question] 
> 1. "라우터를 기준으로 LAN과 WAN이 나뉜다"는 점을 고려했을 때, 서버와 네트워크의 "라우터로 LAN을 다시 네트워크 여러개로 나눌 수 있다(p.30-32)"는 말은 다음 중 어떤 의미일까?
>    
>	a) LAN이라는 하나의 큰 네트워크를 라우터를 통해 소그룹으로 나눈다.
>	(WAN-LAN-subLAN1, subLAN2, ...)
>
>	b) WAN에 연결된 LAN을 복수의 라우터에 의해 복수개로 나눈다. 
>	(WAN-LAN1, LAN2, ...)
> > [!todo]- LAN의 분리
> > - a에 가까움
> > - LAN이라는 큰 네트워크를 라우터로 여러 서브 네트워크로 분할
> > - ex) 회사 LAN = {개발팀 LAN, 서버 LAN, 관리 LAN}
> > - 보안, 트래픽 제어, 장애 격리 가능

## OSI 참조 모델

- 정리
1. OSI 7 Layer
	1) Application       ┓ 
	2) Presentation    ┣  통신 서비스 기능
	3) Session             ┛
	4) Transport         ━  데이터 전송 기능을 보완
	5) Network            ┓
	6) Datalink            ┣  데이터 전송 기능
	7) Physical            ┛

> > [!todo]- Network vs Transport Layer
> > - Network (L3)
> >	- 어디로 갈지 결정
> >	- IP, 라우팅
> >- Transport (L4)
> >	- 제대로 전달되었는지 책임을 짐
> >	- 순서 보장, 재전송, 흐름 제어, 포트 번호로 프로세스 식별 등
> >	- TCP / UDP
> >
> >⇒ Network = 길찾기, Transport = 택배 기사 + 등기 서명
