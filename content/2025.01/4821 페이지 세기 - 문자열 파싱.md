# [❌ 4821 페이지 세기](https://www.acmicpc.net/problem/4821)
#문자열_파싱 #알고리즘 #백준 

> [!abstract] 요약
> - parsing하려는 delimiter가 몇 개인가?
> 	- 여러개라면 인자로 delimiter를 받아 유연한 parser를 구현할 수 있음
> 
> - 문자열을 parsing할 때 어떤 방법을 쓸 것인가?
> 	- BEST: 1회 순회할 때 모든 delimiter와 token을 파싱하는것이 $O(n)$으로 유리하지만
> 	- SOSO: 코드 가독성을 고려했을 때 몇 단계에 걸쳐 수행
> 	- WORST: `find()`로 모든 delimiter를 찾아 순회 ($O(n^2)$)

## 1. 문제
- 입출력 
	- 문서의 총 페이지 수, 복수의 페이지 범위가 주어졌을 때 최종적으로 인쇄할 페이지 수를 출력
- 조건
	- 페이지 범위가 유효하지 않다면 무시 (시작 페이지 수(`low`) > 종료 페이지(`high`) 수인 경우)
	- 페이지 범위가 총 페이지 수를 넘길 경우 무시
	- 중복된 페이지는 한번만 출력
	- `comma(,), hyphen(-), numeric` 으로 이루어진 문자열로 주어진 페이지를 parsing	

## 2. 접근
- 접근 방식
	1. 문자열을 parsing 
	2. 각 범위에 대해 `low == high`일 때 까지 `unordered_set`에 넣기 (중복 제거)

- 막힌 지점
	- parsing하는 절차를 자세히 고려하지 않아 구현이 어려웠음
		: 단순히 `delimiter 기준으로 숫자를 추출`하는 것으로 생각
	- 하나의 반복문에서 delimiter을 `find()`로 인덱스를 찾은 뒤 `substr()`을 통해 `low`, `high`를 추출
		- 하나의 반복문에서 두개의 문자를 파싱하려니 코드가 복잡해짐
		- `find()`를 계속 사용하려니 `O(n)`이 누적됨
		- delimiter를 인덱스로 관리하려니 계산실수가 잦고, 범위(하이픈) 없이 단독으로 주어지는 페이지는 파싱이 어려웠음 

## 3. 핵심 포인트
- 인덱스 대신 string 덧셈으로 token 추출하기
	- 문자열의 문자에 하나씩 접근
	- delimiter가 아니라면 기존 **token 문자열에 더하기**
	- delimiter라면 하나의 token으로 분리하고 token변수 초기화
- 마지막 delimiter 이후의 마지막 token도 더해줘야 함
- `substr()`은 계속해서 복사본을 만들기 때문에 메모리 측면에서 부담이 될 수 있음
- parser를 함수로 만들 때 delimiter를 인자로 주어 여러 문자를 파싱할 수 있음
- `atoi()` 대신 `from_chars()`를 사용하면 더 효율적이지만 한자리 숫자에만 사용 가능
