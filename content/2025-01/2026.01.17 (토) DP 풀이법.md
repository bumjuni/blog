# [⭕️  계단 오르기](https://www.acmicpc.net/problem/2579)
#알고리즘 #백준 #DP 

> [!abstract] 요약
> - dp는 '완전무결한 일반화 로직'을 찾는 것이 아니라 `부분 문제 간의 반복된 구조(점화식)`을 찾는 알고리즘임
> - 무작정 일반화부터 수행하지 말고 dp\[0]부터 차근차근 접근해야 함 (의심 걱정 X)

## 1. 문제
- 입출력
	- 총 계단의 수와 각 계단의 점수  배열이 주어졌을 때, 계단을 올라서 얻을 수 있는 최대 점수값  출력

- 조건
	- 계단은 한번에 한칸 또는 두칸까지 오를 수 있음
	- 3개의 계단을 연속해서 오를 수 없음
	- 마지막 계단은 반드시 밟아야 함

## 2. 접근
- 접근 방식
	1. dp배열을 {int, int}의 pair 셀 N+1개로 선언
	2. 초깃값 제공
		- dp\[0]  = {0, 0} (시작 지점은 점수 0개, 0칸 연속)
		- dp\[1] = {scores\[1], 1} (첫번째 칸은 점수 scores\[1], 1칸 연속)
		- dp\[2] = {scores\[1] + scores\[2], 2}
	3. dp\[3]부터는 3가지 경우의 수 비교해서 최댓값 기록
		- dp\[i-1]에서 한 칸 올라오는 경우 (연속된 칸이 2 미만일 경우)
		- dp\[i-2]에서 두 칸 올라오는 경우
		- dp\[i-3]에서 두 칸, dp\[i-1]에서 한 칸 올라오는 경우
	4. 마지막에 `dp\[N].first`을 return

- 잘못된 부분
	- 테스트 케이스는 모두 통과해서 정답이었지만, 불필요한 비교를 하였음
	- 각 비교는 아래 case를 의미함. 
		- case 1-2은 case 3은 같은 내용이므로 불필요함.
		- case 1-1은 3개의 계단을 연속해서 밟았으므로 잘못됨. (코드 상에서는 연속된 계단 수가 2이므로 if문에 걸리지 않음)![[제목_없는_아트워크.jpg]]
	- dp\[0] → dp\[1] → dp\[2] → dp\[3]부터 하나씩 계산하면서 로직을 만들지 않고, 무작정 일반화부터 적용하다 보니 잘못된 케이스를 비교하게 됨

## 3. 핵심 포인트
- dp 문제 풀이 방법
	- 초기 케이스부터 계산한 뒤 일반화 할 수 있는 공통된 부분을 묶어서 for문으로 작성해야 함
	- 무작정 일반화부터 시도하면 안됨
	- 이 문제의 경우 'dp\[3]부터 dp\[N]까지는 공통된 비교를 수행하면 된다'를 발견한 뒤 for문으로 묶었어야 했음
	
- dp문제에서 이전 케이스를 완전히 믿는 방법
	- 나의 경우 dp문제를 풀 때 이전 케이스가 완벽하지 않으면 어떡하지? 라고 걱정하며 모든 케이스를 고려하여 완벽함을 증명하려고 하는 경향이 있음
	- dp를 '완벽한 로직'을 발견하는 알고리즘이 아니라 계산을 수행하다 보니 발견되는 공통된 부분을 찾는 '점화식'으로 접근하면 이전 케이스의 완벽함을 증명할 필요가 없음
	- 알고리즘 동아리에서 강의를 들을 때도 dp를 **'부분 문제들 간에 반복되는 구조**'를 찾는 문제 해결 방법이라고 한 바가 있음
