#프로그래머스 #알고리즘 #구현

## [문제](https://school.programmers.co.kr/learn/courses/30/lessons/389478)
- 입력
	- 택배 박스를 그림과 같이 쌓을 때, 총 택배 상자의 개수 `n`, 가로로 놓는 상자의 개수 `w`, 찾을 택배 상자의 번호 `num`
- 출력
	- 쌓인 택배 상자에서 `num`번째의 택배 상자를 찾기 위해 꺼내야 하는 택배의 수 (`num`번쨰의 택배 상자를 포함하여, 위에 쌓인 상자의 수)

## 분석 (Plan)
- 시간 복잡도: $O(n)$
- 알고리즘: 완전탐색

- 사유
	- 쌓는 방식에 규칙성은 있으나, 이를 수식화 하기 어렵다고 판단
	- `n`이 100 이하이기 때문에 완전 탐색 가능
- 구현 방식
	- 1부터 `n`까지 택배 상자를 쌓으며 `num`위의 택배 상자 개수를 셈
	```
	// 택배 박스 쌓기
	1. 1부터 `n`까지 `w`개의 배열 중 `j`번째에 하나씩 택배 상자를 추가
	2. 이때 반복자 `i`가 `num`과 같으면 가로 위치 `row`, 세로 위치`height` 기억
	
	// 택배 박스를 쌓는 규칙 정의
	1. 증가 폭 `j`는 0에서 시작하여 1씩 늘어남
	2. 반복자 `i`가 `w`으로 나누어 떨어지면 1씩 감소
	   (`j`는 0~`w`의 구간을 반복하여 택배 상자가 들어갈 배열을 결정)
	```

## 구현 (Do)
```
FOR (i=1 to n, ++i) {
	IF i == num
		row = j
		height = 박스 배열 중 j번째의 현재 사이즈 
				 (`num`이전에 쌓인 박스의 수)
	박스 배열의 j번째에 i 추가
	
	IF i % w == 0 {
		gap의 값을 1과 -1 사이에서 토글링
		CONTINUE	
	}
	j를 gap만큼 중가
}

answer = 박스 배열의 row 번째의 현재 사이즈 - height
```

## 결과 (Check)
- 정답이었지만 풀이가 깔끔하지 못한 것 같아 아쉽다


## 개선 (Action)
- 개선 코드
	- 수식을 이용하여 지그재그로 쌓은 택배 박스의 위치와 증가할 값을 파악하고, `n`이 넘지 않을 때까지 더하며 `num`위에 쌓인 택배의 개수를 셈
	```
	while (num <= n) {
		answer++;
		num += (w - 1 - (w + num - 1) % w) * 2 + 1;
	}
	```
