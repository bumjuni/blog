#프로그래머스 #알고리즘 

## [문제](https://school.programmers.co.kr/learn/courses/30/lessons/214288)
- 입력
	-  상담 유형의 종류 `k`, 상담원의 인원 `n`, {상담 시작 시간, 상담 시간, 상담 유형}의 배열
- 출력
	- 상담원 `n`명을 `k`개의 유형에 배치했을 때 참가자가 기다리는 최소 시간

## 분석 (Plan)
- 시간 복잡도: $O(N^2)$
- 알고리즘: 그리디

- 구현 방식 
	- 상담원을 `k`명 ~ `n`명으로 증가시키며, 각 유형의 대기 시간을 계산하여 가장 대기 시간이 가장 긴 유형에 추가 배치
	- 상담원 최대 20명에 대해 `reqs`최대 300개를 중첩하여 계산해야 하므로 입력값은 대략 $10^3$이라 판단함

## 구현 (Do)
	```
	FOR (j = 0 to n, ++j) {
		FOR (i = 0 to reqs.size(), ++i) {
			// 대기 시간 계산
			type = 새로운 req의 상담 유형
			min_end_idx = end_time[type]에서 가장 빨리 끝나는 상담원의 인덱스
			min_end = end_time[type]에서 가장 빨리 끝나는 시간
			IF min_end > 새로운 req의 상담 요청 시작 시간 {
				waiting_time[type] += min_end - 상담 요청 시작 시간
			}
			end_time[type][min_end_idx] += 상담 지속 시간
		}
		// 상담원 배치
		max_type = waiting_time 배열에서 대기 시간이 가장 긴 유형
		end_time[max_type].push_back(0);
	}
	```

## 결과 (Check)
- 실패
- `waiting_time`과 `end_time`의 값을 조작하는 부분에서 계속해서 segfault 발생
